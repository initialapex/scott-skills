# STM32 with CubeMX and the HAL (LL as a supplement)

Contents: how the layers map · living with CubeMX regeneration · handles and the
composition root · a port: I2C · a port: UART with DMA and idle line · callbacks ·
FreeRTOS · priorities · LL · DMA and cache · clocks and low power · pitfalls

Scope: STM32Cube HAL/LL in C, STM32CubeIDE or CMake with `arm-none-eabi-gcc`, bare-metal
or FreeRTOS (the CMSIS-RTOS v2 wrapper that CubeMX generates, or FreeRTOS directly).
Function and macro names are the HAL's; family-specific details (F0/F1/F4/L4/G0/H7/U5)
differ, so confirm them in the HAL documentation and reference manual of the part in use.

## How the layers map

| Layer | Where |
|-------|-------|
| generated | `Core/`, `Drivers/` (HAL, CMSIS), startup file, linker script: owned by CubeMX |
| app, service, driver, hal, common | your own folders beside `Core/` (`firmware/...`); no HAL includes |
| port | `firmware/ports/stm32/port_stm32_*.c`: the only files that include `stm32xxxx_hal.h` and `main.h` |
| board | `firmware/board/board_<name>.c`: knows `hi2c1`, `huart2`, pins; builds the objects |

## Living with CubeMX regeneration

CubeMX rewrites generated files every time the `.ioc` changes. Only text between
`/* USER CODE BEGIN x */` and `/* USER CODE END x */` survives, so:

- **Put almost nothing in the USER CODE regions.** Three lines are enough:
  `board_init();` and `app_start();` after the `MX_..._Init()` calls (`USER CODE BEGIN 2`),
  and `app_poll();` in the main loop (`USER CODE BEGIN WHILE`), or the creation of the
  app task in `USER CODE BEGIN RTOS_THREADS` when FreeRTOS is generated by CubeMX.
- **Your code lives in separate folders** that the project builds (linked folders in
  CubeIDE, `target_sources` in CMake). Never edit `Drivers/` (the HAL) either; updating
  the firmware package replaces it.
- **Override `__weak` HAL callbacks in your port files**, not in `main.c` or `stm32xx_it.c`.
  The HAL declares callbacks such as `HAL_UART_TxCpltCallback`,
  `HAL_UARTEx_RxEventCallback`, `HAL_GPIO_EXTI_Callback`, `HAL_TIM_PeriodElapsedCallback`,
  `HAL_I2C_MasterRxCpltCallback`, `HAL_SPI_TxRxCpltCallback` as weak; a strong definition in
  your file replaces them with no generated file touched. (With
  `USE_HAL_xxx_REGISTER_CALLBACKS` set to 1, register with `HAL_xxx_RegisterCallback()`
  instead; the weak ones are then unused.)
- **Pin and peripheral changes belong in the `.ioc`**, regenerated, then check the diff:
  a changed pin must also change the board file and, if a clock or a baud rate moved, the
  config the board passes to objects.
- Keep the `.ioc` and the generated sources in version control; a code review sees both.
- Check whether the linker script and startup file are regenerated by your toolchain
  before editing them; custom sections (CCM, external RAM) need a stable place.

## Handles and the composition root

CubeMX defines handles as globals (`I2C_HandleTypeDef hi2c1;`, `UART_HandleTypeDef
huart2;`) and the interrupt handlers use them (`HAL_I2C_EV_IRQHandler(&hi2c1)`). Only the
**board file** refers to them, and passes the pointer to the port object:

```c
/* board_nucleo.c */
extern I2C_HandleTypeDef hi2c1;               /* defined by CubeMX in i2c.c */
static port_stm32_i2c_t s_i2c1;

fw_status_t board_init(void)
{
    port_stm32_i2c_config_t cfg = { &hi2c1 };
    return port_stm32_i2c_init(&s_i2c1, &cfg);
}
```

## A port: I2C

The HAL wants the 7-bit address **shifted left by one**; our interface passes the 7-bit
address, so the port shifts (the most common STM32 mistake, in both directions). The
HAL's `HAL_I2C_Mem_Read()` performs "write register address, repeated START, read", which
is what `write_read` means for a one- or two-byte register pointer; longer prefixes use
separate transmit and receive calls (which end with STOP then START; fine for most
devices, not for ones that require a repeated start).

```c
/* port_stm32_i2c.c */
#include "main.h"                      /* pulls in the HAL */
#include "hal_i2c.h"

typedef struct port_stm32_i2c {
    hal_i2c_t base;                    /* first member */
    I2C_HandleTypeDef *handle;
    osal_mutex_t lock;
} port_stm32_i2c_t;

static uint32_t to_hal_timeout(uint32_t timeout_ms)
{
    return (timeout_ms == OSAL_WAIT_FOREVER) ? HAL_MAX_DELAY : timeout_ms;
}

static fw_status_t map_hal(HAL_StatusTypeDef s)
{
    switch (s) {
    case HAL_OK:      return FW_OK;
    case HAL_TIMEOUT: return FW_ERR_TIMEOUT;
    case HAL_BUSY:    return FW_ERR_BUSY;
    default:          return FW_ERR_IO;    /* HAL_ERROR: HAL_I2C_GetError() tells NACK from bus error */
    }
}

static fw_status_t port_write_read(hal_i2c_t *base, uint8_t addr7, const uint8_t *tx, size_t tx_len,
                                   uint8_t *rx, size_t rx_len, uint32_t timeout_ms)
{
    port_stm32_i2c_t *self = FW_CONTAINER_OF(base, port_stm32_i2c_t, base);
    uint16_t dev = (uint16_t)((uint16_t)addr7 << 1);          /* 8-bit form wanted by the HAL */
    HAL_StatusTypeDef hs;
    fw_status_t st;

    if (rx_len > UINT16_MAX || tx_len > UINT16_MAX || tx_len == 0u) { return FW_ERR_INVALID_ARG; }
    if (osal_mutex_lock(&self->lock, timeout_ms) != FW_OK) { return FW_ERR_BUSY; }

    if (tx_len == 1u) {                                      /* register pointer: repeated START */
        hs = HAL_I2C_Mem_Read(self->handle, dev, tx[0], I2C_MEMADD_SIZE_8BIT, rx,
                              (uint16_t)rx_len, to_hal_timeout(timeout_ms));
    } else if (tx_len == 2u) {
        hs = HAL_I2C_Mem_Read(self->handle, dev, fw_get_be16(tx), I2C_MEMADD_SIZE_16BIT, rx,
                              (uint16_t)rx_len, to_hal_timeout(timeout_ms));
    } else {                                                 /* longer prefix: STOP between the phases */
        hs = HAL_I2C_Master_Transmit(self->handle, dev, (uint8_t *)(uintptr_t)tx,
                                     (uint16_t)tx_len, to_hal_timeout(timeout_ms));
        if (hs == HAL_OK) {
            hs = HAL_I2C_Master_Receive(self->handle, dev, rx, (uint16_t)rx_len,
                                        to_hal_timeout(timeout_ms));
        }
    }
    st = map_hal(hs);
    if (st != FW_OK) { recover_bus_if_needed(self); }        /* re-init, or clock out a stuck slave */
    osal_mutex_unlock(&self->lock);
    return st;
}
```

For a 16-bit register address `HAL_I2C_Mem_Read` sends the high byte first, matching
`fw_get_be16`. Older HAL versions take a non-const data pointer, hence the cast in the
transmit call (keep it in the port). Some series have a known stuck-busy state in the
I2C peripheral after an error; the recovery (`HAL_I2C_DeInit`/`Init`, or toggling SCL as
GPIO) belongs in the port, and the exact procedure is in the errata sheet of the part.

## A port: UART with DMA and idle-line reception

For a receive stream, use `HAL_UARTEx_ReceiveToIdle_DMA()` into a circular buffer and the
`HAL_UARTEx_RxEventCallback(huart, size)` (called on idle line, half- and full-transfer);
copy the newly arrived bytes into the object's ring buffer and signal the consumer. The
HAL callback has no context pointer, so the port keeps a small registry from handle to
object:

```c
#define PORT_UART_MAX 4u
static port_stm32_uart_t *s_uarts[PORT_UART_MAX];       /* filled by port_stm32_uart_init() */

static port_stm32_uart_t *find_uart(const UART_HandleTypeDef *h)
{
    size_t i;
    for (i = 0u; i < PORT_UART_MAX; i++) {
        if (s_uarts[i] != NULL && s_uarts[i]->handle == h) { return s_uarts[i]; }
    }
    return NULL;
}

/* Strong definition of the HAL's weak callback; ISR context (through HAL_UART_IRQHandler). */
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t size)
{
    port_stm32_uart_t *self = find_uart(huart);

    if (self != NULL) { port_stm32_uart_on_rx_event(self, size); }   /* testable shell + logic split */
}
```

`on_rx_event` computes the new bytes since the previous call (`size` is the position in the
DMA buffer, which wraps in circular mode), writes them into the ring buffer, counts an
overflow if it did not fit, and notifies the consumer through the OSAL
(`osal_sem_give_from_isr`). In D-cache parts, invalidate the DMA buffer range before reading
it (see DMA and cache below).

## FreeRTOS

- CubeMX offers FreeRTOS through the CMSIS-RTOS v2 wrapper (`osThreadNew`, `osMutexNew`,
  `osMessageQueueNew`) or the native API. Pick one in the OSAL port and use it everywhere.
- **Time base**: with an RTOS, move the HAL time base off SysTick to a spare timer
  (CubeMX: *SYS -> Timebase Source*), because FreeRTOS owns SysTick. The HAL tick ISR must be
  at least as urgent as any interrupt whose handler waits on a HAL timeout, or those
  timeouts never expire.
- **Interrupt priorities**: set `NVIC_PRIORITYGROUP_4`; an ISR that calls `...FromISR` must
  have a preemption priority number **greater than or equal to**
  `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` (CubeMX shows it in the FreeRTOS settings;
  often 5); set it in the NVIC tab or with `HAL_NVIC_SetPriority()`.
- **HAL timeouts inside tasks** block with `HAL_GetTick()`; they are correct under an RTOS
  but busy-wait: for long transfers use the interrupt or DMA variants plus a semaphore
  from the completion callback, so the task sleeps.
- Heap: `heap_4` plus `configTOTAL_HEAP_SIZE` is a static array in `.bss`; prefer static
  creation (`configSUPPORT_STATIC_ALLOCATION`) so memory use is visible in the map.

## LL (low layer) as a supplement

- LL drivers (`stm32xxxx_ll_*.h`) are `static inline` register helpers: no handle, no state
  machine, near zero overhead. Use them in tight interrupt handlers or code-size-sensitive
  paths (a fast GPIO toggle, an ADC/DMA stream in an ISR).
- **Do not drive one peripheral with both HAL and LL**: the HAL tracks state in the handle,
  and LL calls behind its back leave it inconsistent. Choose one API per peripheral.
- LL is still a port detail: wrap it behind the same HAL interface as the HAL version.

## DMA and cache (F7, H7, and parts with a data cache)

- Buffers must be reachable by the DMA used: on H7, DMA1/2 cannot reach DTCM and BDMA only
  reaches SRAM4; use the memory table in the reference manual and place buffers with a
  section attribute plus the linker script.
- **Clean** (`SCB_CleanDCache_by_Addr`) before a memory-to-peripheral transfer, **invalidate**
  (`SCB_InvalidateDCache_by_Addr`) after a peripheral-to-memory transfer; align address and
  size to 32 bytes, or configure the region as non-cacheable in the MPU.
- Do not let two DMA buffers (or a buffer and a variable) share a 32-byte cache line.
- Concurrency and ownership rules are in [interrupts-concurrency.md](interrupts-concurrency.md).

## Clocks, low power, and watchdog

- `SystemClock_Config()` is generated: change clocks in CubeMX, then re-check every
  consumer (UART baud rate, I2C timing register, timer periods); never hand-edit
  `SystemCoreClock`.
- **STOP/STANDBY modes**: after wake-up from STOP, the system clock needs to be
  reconfigured (`SystemClock_Config()`), and the HAL tick may need to be suspended and
  resumed (`HAL_SuspendTick`/`HAL_ResumeTick`) around the sleep; do not enter STOP with a
  DMA transfer pending.
- **IWDG** (`HAL_IWDG_Refresh`) is fed by the supervisor task; freeze it during debug
  with the DBGMCU option so a breakpoint does not reset the chip.
- Writing option bytes or enabling readout protection changes the device permanently:
  show the programmer command and let the developer run it.

## Build

- GCC options for production: `-Os` or `-O2`, `-ffunction-sections -fdata-sections`,
  linker `-Wl,--gc-sections`, `--specs=nano.specs`, `-fstack-usage`, and `-Wall -Wextra` for
  your code only. `printf` with `%f` needs `-u _printf_float` and costs several KB of flash.
- Check the `.map` and `arm-none-eabi-size` output after each feature
  ([robustness.md](robustness.md)).

## Pitfalls

- Passing an unshifted 7-bit I2C address to the HAL (or shifting twice).
- Editing generated code outside USER CODE regions; business logic in `stm32xx_it.c`.
- A global `hi2c1` used by drivers directly; the drivers cannot then be tested or reused.
- `HAL_Delay()` in an ISR or at a priority below SysTick (it never returns), or with the
  RTOS tick taken from SysTick and a HAL timebase left on it.
- DMA buffer on the stack, in DTCM, or sharing a cache line; missing cache maintenance.
- Mixing HAL and LL on one peripheral; ignoring the return of `HAL_xxx` calls (`HAL_BUSY`
  after an aborted transfer is common).
- Calling `...FromISR` from an interrupt more urgent than the RTOS allows.
- Assuming the `.ioc` and the generated code are in sync after a manual edit of either.
